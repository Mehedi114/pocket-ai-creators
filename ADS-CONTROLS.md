# Advertising controls

Creator Login → Account & help → Advertising controls. Master ON/OFF and individual banner/popunder/Social Bar switches are stored in Supabase `ph_ad_settings`. The migration `homepage_ad_controls` has been applied to the existing project. Defaults preserve previous behavior (all placements allowed, still subject to visitor consent). Anonymous users can read these public booleans, not update them; authenticated updates require `ph_is_admin()` through RLS. No provider credentials or editable script HTML are stored here.

The public homepage checks the policy only after visitor ad consent, before requesting publisher resources. Fetch failures/missing/malformed policy fail closed. Active visible opted-in pages recheck every 60 seconds; settings may be cached in memory for 30 seconds between manual attempts. If a vendor script has already run and is switched off, the page reloads to stop its in-page handlers. Already opened external windows cannot be closed remotely. This control does not override visitor consent or enable advertising on private/admin/Studio pages.

A site-owner ON switch cannot guarantee an impression. Existing publisher URLs are retained unchanged. Register/approve `pockethelper.phapps.workers.dev` in the ad-provider dashboard, confirm the banner code belongs to the approved site, then test the homepage after explicit ad consent. The Ad settings dialog includes script-load/error diagnostics; script loaded does not mean ad rendered or revenue recorded. Ad blocking, browser privacy restrictions, network reachability and provider inventory remain possible causes. Actual delivery has not been verified in this environment.

Validation: mocked owner saves/failure handling, anonymous database UPDATE privilege denied, SQL RLS policy checks, consent preservation, owner and placement OFF, policy network/schema failure, accept/reject race, existing full suite and deployment/Worker tests. Production UI becomes available only after PR merge/deployment. AI remains intentionally disabled.
